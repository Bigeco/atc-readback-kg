입력 → 모델 → 출력

세미콜론 왼쪽은 녹음 파일마다 바뀌는 입력, 오른쪽은 미리 만들어 두고 재사용하는 입력이다. 항목을 누르면 아래에 정의가 나온다.

모듈별 입출력 정의

송신 i 하나가 M1부터 M5까지 차례로 처리되며 그래프 G가 커진다. 각 모듈 아래 회색 줄은 같은 교신 예시가 그 모듈에서 어떻게 바뀌는지 보여준다.

예시 교신 — ATCO: "Delta twenty six forty two, runway two six left, taxi via alpha bravo, hold short of runway two six right" / PILOT: "taxi via alpha bravo, hold short two six right, Delta twenty six forty two"

입력출력M# 모듈
M0정적 자원 구축오프라인, 한 번

입력

  • Donto: DLR 사양서·명령 표 PDF
  • Dreg: FAA JO 7110.65BB PDF
  • Dapt, Dfac: OurAirports, OpenStreetMap
  • Dtel: FAA JO 7340.2 항공사 호출 이름

출력

  • O → ontology.json
  • KR → rules.json
  • KS → katl.json, airlines.json
  • Vdom: STT 프롬프트 어휘

생성 코드가 PDF 원문과 대조해 근거가 없으면 생성을 멈춘다. 예: HOLD_SHORT ↔ DLR 표 Ground hold types 줄, FAA §2-4-3 b항.

M1a송신 분할 (M1 STT)

입력

  • a: 피드별 음성
  • C: 파일 이름에서 읽은 공항·위치·시각

출력

  • si = [tsi, tei): 송신 구간 (UTC)
  • xi: 송신 음성 조각

VAD로 무음 0.3초 기준 분할, 30분 파일 사이 겹침은 UTC로 중복 제거. 예: 관제사 송신 02:31:05–02:31:11, 조종사 송신 02:31:12–02:31:16

M1b맥락 바이어싱 STT

입력

  • xi: 송신 음성 조각
  • Vdom: 공항·항공사 어휘 (KS)
  • Fact: 직전에 나온 콜사인

출력

  • wi: 전사 텍스트
  • ci: 인식 신뢰도
  • langi: 언어

Whisper large-v3 + 환각 필터. 예: "Delta twenty six forty two, runway two six left, taxi via alpha bravo, hold short of runway two six right"

M2a화자 역할·턴 분리

입력

  • wi와 앞뒤 송신

출력

  • ri ∈ {ATCO, PILOT}: 화자 역할
  • 한 송신에 두 사람 말이 붙어 있으면 턴으로 분리

콜사인 위치(앞이면 관제사, 뒤면 조종사)와 시설 이름 규칙. 예: 첫 송신 = ATCO, 둘째 송신 = PILOT

M2b온톨로지 기반 지시 추출

입력

  • (wi, ri): 텍스트와 역할
  • O: 명령 종류·값 형식 (ontology.json)
  • E: 예시

출력

  • ui = (ĉi, Ii): 콜사인 언급, 지시 목록
  • 지시 ι = (κ 종류, v 값, μ 단위, q 한정어, g 대상)

Qwen3-4B(로컬) + 규칙 문법 보충, 어휘 단서로 환각 검증. 예: ĉ = "Delta 2642", I = {TAXI_VIA 경로 A,B 목적지 26L; HOLD_SHORT 26R}

M3정규화·grounding·개체 해소

입력

  • ui
  • KS: 활주로·유도로·항공사 목록
  • G<t: 지금까지의 그래프
  • Ci: 맥락

출력

  • fi: 항공편 노드
  • Ĩi: 대상이 KS 노드로 연결된 지시 (없으면 ⊥)
  • Ai: 플래그 (ASR_CORRECTED 등)

예: "Delta 2642" → Flight DAL2642, "two six right" → Runway KATL 26R. 목록에 없는 유도로면 KB_VIOLATION.

M4증분 Temporal KG 구축

입력

  • Gt-1, (fi, Ĩi), 송신 정보
  • KR: 대체 관계, 복창 필수 (rules.json)
  • Θkg: 복창 시간창 20초, 최대 유효시간 (kg_build.json)

출력

  • Gt: 송신·지시 노드 추가
  • READBACK_OF 간선 (복창 연결)
  • 지시의 유효 구간 τ

예: HOLD_SHORT 26R 유효 [02:31:05, …), 조종사 송신 –READBACK_OF→ 관제사 송신. 이후 "cross runway 26R"이 오면 그 시각에 종료.

M5규칙 추론·이상 탐지

입력

  • Gt
  • KR: 복창 필수 13종, 활주로 점유 4종
  • 규칙 ρ1–ρ7

출력

  • Y = {(y, π, γ)}: 경고 라벨, 근거 부분그래프, 신뢰도
  • 복창 상태: MATCH / PARTIAL / MISMATCH

예: 조종사가 "two six left"로 복창하면 MISMATCH (26R ≠ 26L). 20초 안에 복창이 없으면 NO_READBACK.

M6시점 질의·시각화

입력

  • G, 시각 t, 질의 템플릿 q

출력

  • Q(G, t, q): 답과 근거 부분그래프
  • 웹 데모 화면

예: "02:32에 26R 앞에서 대기 중인 항공편은?" → DAL2642

M7진단 하네스RQ4 전용

입력

  • J: M1a–M5 중간 산출물 로그
  • 국가별 15–20개 송신의 정답

출력

  • CSR: 콜사인 인식률
  • CmdF1: 명령 인식 F1
  • m†: 처음 실패한 모듈

한국·일본 교신에서 어느 모듈 때문에 실패하는지 찾는다. ICAO 규칙(rules.json)은 아직 원문 미검증.
